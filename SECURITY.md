# Security Policy

## Reporting a Vulnerability

We take security issues in Padavan seriously.

If you believe you have found a security vulnerability in this project, please report it privately using GitHub's **Private Vulnerability Reporting** feature.

Please do **not** create a public GitHub issue or publicly disclose the vulnerability before the maintainers have had an opportunity to investigate it.

### What to include

When reporting a vulnerability, please provide as much information as possible, including:

* A clear description of the vulnerability.
* The affected Padavan version, commit, or branch.
* The affected router model or hardware platform, if applicable.
* Steps to reproduce the issue.
* The expected and actual behavior.
* Relevant logs, configuration details, or error messages.
* A proof of concept (PoC), if available.
* Any suggested mitigation or fix, if available.

Please avoid including passwords, private keys, API tokens, or other sensitive credentials in the report.

## Scope

Security reports may include issues affecting:

* Padavan firmware.
* Network services included in the firmware.
* Web management interfaces.
* Authentication and authorization.
* Firmware update mechanisms.
* Build scripts and security-sensitive components.
* Third-party components distributed as part of the firmware.

## Response

The maintainers will review valid security reports and may request additional information to reproduce and investigate the issue.

Depending on the severity and complexity of the vulnerability, investigation and remediation may take time.

## Responsible Disclosure

We ask security researchers to allow reasonable time for investigation and remediation before publicly disclosing a vulnerability.

Once a vulnerability has been addressed, the maintainers may publish information about the issue, including the affected versions, fixed versions, and appropriate acknowledgements.

Thank you for helping improve the security of Padavan and its users.
